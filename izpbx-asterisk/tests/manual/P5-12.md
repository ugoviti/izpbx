# P5-12 — Real Let's Encrypt certificate with a public FQDN (manual)

The automated test P3-16 covers the Let's Encrypt logic of izPBX 22.17 with a
simulated `fwconsole` (request at start, `cron.env`, daily renewal restarting
the web server only when the certificate changes). This procedure checks the
real exchange with Let's Encrypt, which needs a public name reachable from the
Internet on port 80.

## About "staging"

The FreePBX 17 certificate manager (certman) can use the Let's Encrypt
staging server only through its PHP API, and the address it uses for staging
(`acme-staging.api.letsencrypt.org`, ACME v1) has been switched off by Let's
Encrypt. Use the **production** Let's Encrypt server with a test name (for
example `pbx-test.<your domain>`): the rate limits allow several certificates
per week for the same name, more than enough for this procedure. Do not repeat
the procedure in a loop.

## What you need

- A public DNS name (A record) pointing to the host, for example
  `pbx-test.example.com`.
- Port 80 of the host reachable from the Internet (the HTTP-01 challenge),
  and port 443 to check the result.
- izPBX 22.17 with FreePBX installed on that host.

## Steps

### 1. Configure .env

```bash
APP_FQDN=pbx-test.example.com
HTTPD_HTTPS_ENABLED=true
LETSENCRYPT_ENABLED=true
LETSENCRYPT_COUNTRY_CODE=IT
LETSENCRYPT_COUNTRY_STATE=Firenze
SMTP_MAIL_TO=admin@example.com      # the Let's Encrypt account e-mail (LETSENCRYPT_EMAIL)
APP_PORT_HTTP=80
APP_PORT_HTTPS=443
```

### 2. Start the container and follow the request

```bash
docker compose up -d
docker logs -f izpbx 2>&1 | grep -i -E 'letsencrypt|certificate'
```

Expected in the log: the request for `pbx-test.example.com`, then the
certificate set as default. Errors usually mean that port 80 is not reachable
or that the DNS name does not point to the host.

### 3. Check the certificate

```bash
docker exec izpbx fwconsole certificates --list
echo | openssl s_client -connect pbx-test.example.com:443 -servername pbx-test.example.com 2>/dev/null \
  | openssl x509 -noout -issuer -subject -dates
```

Expected: issuer Let's Encrypt (R10/R11 or E5/E6), subject
`CN = pbx-test.example.com`, validity of 90 days. Open
`https://pbx-test.example.com/admin` in a browser: no certificate warning.

### 4. Renewal from cron.daily

Run the daily job by hand, as cron would (empty environment):

```bash
docker exec izpbx sh -c 'cat /etc/izpbx/cron.env; env -i /bin/sh /etc/cron.daily/freepbx-le-renew; echo rc=$?'
docker logs --since 5m izpbx 2>&1 | grep -i -E 'renew|restart|httpd'
```

Expected: exit code 0. A certificate far from its expiry is not renewed, so
Apache is **not** restarted (the job restarts it only when the certificate
fingerprint changes). To see a real renewal, force it once and run the job
again:

```bash
docker exec -u asterisk izpbx fwconsole certificates --updateall --force
docker exec izpbx sh -c 'env -i /bin/sh /etc/cron.daily/freepbx-le-renew; echo rc=$?'
```

Then the new certificate (later "notBefore" date in step 3) is served and the
log shows the web server restart.
