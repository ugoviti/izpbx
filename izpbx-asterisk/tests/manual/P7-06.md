# P7-06 — 22.17.0-rc1 on real volumes (manual)

The automated tests migrate fixtures generated by izPBX 20.16.x itself
(P0-04, P0-08a…f): every version from 20.16.0, an installation born on
FreePBX 15, an external database, a large volume, commercial modules
simulated. This procedure checks the release candidate **22.17.0-rc1** on
copies of **at least 3 real volumes** (Q5), among them:

- one with a **licensed FOP2**;
- one with a **commercial module** (a real license, eg. `sysadmin`,
  `endpoint`, `vmnotify`).

Evidence for each volume: the inventory diff (empty) and the final report.

## What you need

- The image `izdock/izpbx-asterisk:22.17.0-rc1` (or the Gitea registry
  image of the same digest).
- For each volume: a copy of `data/izpbx` and a dump of the FreePBX and CDR
  databases of an izPBX 20.16.x in production, taken with izPBX stopped
  (README "Upgrade from 20.16 to 22.17", step 2). **Never run this on the
  production volume and database.**
- A test host **isolated from the providers and the phones** of production:
  a copy of a real PBX registers its trunks and answers its phones. Block
  outgoing SIP and IAX from the test host (UDP/TCP 5060, 5061, 5160, UDP 4569)
  or disconnect it from the networks of the phones, but keep HTTPS to the
  Internet (FreePBX mirror, FOP2 package).
- For the licensed FOP2 volume: the same MAC address on the licensed
  interface (see `izpbx-asterisk/tests/manual/P4-15.md`).

## Steps (for each volume)

### 1. Restore the copy on the test host

```sh
mkdir -p /opt/izpbx-rc && cd /opt/izpbx-rc
# compose.yml and default.env of 22.17.0-rc1, your .env of production
tar -xzf /path/to/izpbx-20.16-data.tar.gz          # -> data/izpbx
docker compose up -d db
gzip -dc /path/to/izpbx-20.16-db.sql.gz | docker compose exec -T db sh -c 'mariadb -uroot -p"$MYSQL_ROOT_PASSWORD"'
```

Set `image: docker.io/izdock/izpbx-asterisk:22.17.0-rc1` in `compose.yml`.

### 2. Checks, then migration

```sh
docker compose run --rm --no-deps --entrypoint izpbx-preflight izpbx
```

Record every `BLOCK` and `INFO` line. A `BLOCK` is a finding for this
procedure when its message is wrong or its instructions do not work; fix the
volume copy as the message says and run the checks again.

```sh
echo "IZPBX_MIGRATE_FREEPBX=true" >> .env
time docker compose up -d izpbx
until docker compose ps --format '{{.Health}}' izpbx | grep -qx healthy; do sleep 10; done
```

If the container stays unhealthy: `docker compose logs izpbx | grep -E 'MAINTENANCE|VERIFICATION|error'`
and `data/izpbx/.izpbx-migration/verify-*.txt` are the evidence of the
failure.

### 3. Evidence

```sh
docker compose exec izpbx sh -c 'izpbx-inventory --diff /data/.izpbx-migration/inventory-before.json \
  /data/.izpbx-migration/inventory-after.json --mapping /data/.izpbx-migration/mapping.tsv; echo "exit $?"'
docker compose exec izpbx cat /data/.izpbx-migration/report.txt
docker compose logs izpbx | grep -E 'migration: (FreePBX 16 ->|snapshot|database)' 
```

Expected: `exit 0` (no difference), the report with the snapshot, the
modules left out and the commercial modules to reactivate.

### 4. Functional checks

- FreePBX web interface: login, Dashboard without errors, **Apply Config**
  works; Admin > Modules Admin: no module Broken or "Needs upgrade" left
  apart from the commercial ones to reactivate.
- Two extensions register (a converted ex chan_sip one if the volume had
  them; a phone that sent to 5160 must still register there), call each
  other with audio both ways; voicemail left and heard (also in UCP).
- Inbound and outbound call on a trunk, **only** with a test trunk or after
  re-enabling the provider access for this check alone.
- Recordings and voicemail of 20.16 are listed and play (CDR reports).
- Custom prompts, music on hold, IVR, queues, ring groups, time conditions,
  conferences (ConfBridge) work as on 20.16.
- **Licensed FOP2 volume**: `izpbx-asterisk/tests/manual/P4-15.md`, steps 3 and 4 (the panel
  starts licensed, not in demo mode).
- **Commercial module volume**: reactivate the module listed by the report
  with its license (Admin > System Admin > Activation, or as the vendor
  says), then the module is Enabled and its page works.
- Phonebook entries, if any: the Contact Manager group "Phonebook (izPBX
  20.16)" and a speed dial `*10<code>`.

### 5. Optional, on one volume: rollback

```sh
docker compose stop izpbx
docker compose run --rm --no-deps --entrypoint izpbx-rollback izpbx
sed -i '/^IZPBX_MIGRATE_FREEPBX=/d' .env
sed -i 's|izpbx-asterisk:22\.17\.0-rc1|izpbx-asterisk:20.16.22|' compose.yml
docker compose up -d izpbx
```

izPBX 20.16.22 starts healthy with the data of before.
