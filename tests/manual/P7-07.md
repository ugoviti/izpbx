# P7-07 — Release 22.17.0: tag, Gitea registry, Docker Hub (manual)

The release is the only step that publishes code and images: it is done by
hand, with the workflows of `.gitea/workflows`. This procedure lists the
steps and the checks; the result is `docker pull izdock/izpbx-asterisk:22.17.0`
working on amd64 and arm64, and the smoke test T2 (new installation with
the default `.env`) green on both.

## Before the release

- [ ] Every other item of the checklist is `[x]`, the manual ones included
      (P7-06: the release candidate on at least 3 real volumes).
- [ ] **arm64**: the release workflow builds `linux/amd64` only
      (`platforms` of `.gitea/actions/build-push`). The arm64 image needs
      P6-02 (multi-arch build in CI) and P4-23 (migration on arm64) done
      first; otherwise release amd64 only and leave the arm64 check of this
      procedure open.
- [ ] `feature/22.17` merged into `main` (pull request: `lint` and `all-done`
      green). `main` now holds 22.17; `release/20.16` exists (P6-05).
- [ ] The CHANGELOG entry `## [22.17.0] - Unreleased` gets the release date:
      `## [22.17.0] - YYYY-MM-DD`, committed on `main`.
- [ ] `compose.yml` on `main` has `image: docker.io/izdock/izpbx-asterisk:22.17.0`.

## 1. Tag and Gitea build

```sh
git checkout main && git pull
git tag -a 22.17.0 -m "izPBX 22.17.0"
git push origin 22.17.0
```

The tag starts `izpbx-release` (Repository > Actions). Check:

- [ ] the job is green, with the image checks of build-push (verify E1);
- [ ] the log of "compute tags" lists `22.17.0`, `22.17`, `22`,
      `22.17.0-<run>` and **no `latest`** (`latest: branch`: the version is
      not on `release/20.16`, V3);
- [ ] the Gitea registry has `izpbx-asterisk:22.17.0` with those tags; the
      `latest` of the registry is still a 20.16 image.

## 2. Check the Gitea image

On a test host, with the Gitea registry image (same digest that will be
published):

```sh
mkdir -p /opt/izpbx-t2 && cd /opt/izpbx-t2
# compose.yml and default.env of the tag 22.17.0
cp default.env .env      # change the passwords
sed -i 's|docker.io/izdock/izpbx-asterisk:22.17.0|<gitea-registry>/<owner>/izpbx-asterisk:22.17.0|' compose.yml
docker compose up -d
until docker compose ps --format '{{.Health}}' izpbx | grep -qx healthy; do sleep 10; done
```

Smoke test T2:

- [ ] FreePBX 17 web interface, admin user created, Apply Config;
- [ ] UCP login (port `APP_PORT_UCP_HTTP`);
- [ ] FOP2 panel (with `FOP2_ENABLED=true`, demo mode);
- [ ] XML phonebook `/pb` answers;
- [ ] fail2ban running (`docker compose exec izpbx fail2ban-client status`);
- [ ] msmtp: `printf 'Subject: izPBX test\n\ntest\n' | docker compose exec -T izpbx sendmail <your address>`
      arrives (with `SMTP_*` set);
- [ ] `docker compose exec izpbx asterisk -V` reports the `ASTERISK_VER` of `versions.env`.

## 3. Promotion to Docker Hub

Repository > Actions > **izpbx-promote** > Run workflow:

| Input | Value |
|---|---|
| version | `22.17.0` |
| latest | **unchecked** (it is checked by default: `latest` stays on 20.16 until Q1) |
| github | checked (pushes the tag and `main` to GitHub, fast-forward only) |
| branch | `main` |
| dockerhub | checked |

Check:

- [ ] gitleaks green (full history, private rules);
- [ ] GitHub has the tag `22.17.0` and `main` at the tagged commit;
- [ ] Docker Hub has `22.17.0`, `22.17`, `22` with the **same digest** as
      the Gitea image; `latest` is unchanged (still the 20.16 digest):

```sh
docker buildx imagetools inspect izdock/izpbx-asterisk:22.17.0
docker buildx imagetools inspect izdock/izpbx-asterisk:latest     # still 20.16.x
```

## 4. Pull and smoke test from Docker Hub

On an **amd64** host and on an **arm64** host:

```sh
docker pull izdock/izpbx-asterisk:22.17.0
docker image inspect -f '{{.Architecture}}' izdock/izpbx-asterisk:22.17.0
```

then the smoke test T2 of step 2 with `compose.yml` of the tag unchanged
(image `docker.io/izdock/izpbx-asterisk:22.17.0`).

- [ ] amd64: pull, architecture `amd64`, T2 green;
- [ ] arm64: pull, architecture `arm64`, T2 green (needs P6-02).

## 5. After the release

- [ ] GitHub release page for `22.17.0` with the CHANGELOG entry and the
      link to the README section "Upgrade from 20.16 to 22.17";
- [ ] the README "Supported tags" on Docker Hub and GitHub shows 22.17
      (production) and 20.16 with `latest` (security fixes until 2027-01-01);
- [ ] the weekly rebuild of the next Monday builds both branches (P6-05).
